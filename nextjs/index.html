Bab 01FONDASI

Next.js adalah rumah. Wallet adalah tamu yang membawa kuncinya sendiri.

Aplikasi Web3 tetap aplikasi web. Ia punya routing, form, state, dan error. Yang berbeda: sebagian state tinggal di chain, dan sebagian izin tinggal di wallet pengguna. Next.js membantumu memisahkan halaman yang bisa dirender di server dari bagian yang harus berjalan di browser.

  • Menjelaskan pembagian tugas Next.js, Wagmi, Viem, wallet, dan kontrak.
  • Membedakan data yang boleh dirender di server dan data yang harus dibaca wallet.
  • Memahami kenapa koneksi wallet bukan autentikasi dengan sendirinya.
  • Menyusun urutan delapan target tahap ini menjadi satu alur layar.

Yang berubah dari aplikasi web biasa

Di aplikasi web biasa, server biasanya memegang kebenaran: data pengguna ada di database, sesi ada di cookie, dan tombol dikendalikan oleh role. Di dApp, kebenaran state ada di chain. Frontend hanya membaca salinan dan mengirim permintaan perubahan. Wallet memegang kunci dan meminta pengguna menyetujui setiap perubahan yang mengeluarkan uang atau memberi izin.

Artinya ada tiga sumber state yang harus kamu tampilkan dengan jujur:

  • State chain. Saldo, pemilik, total deposit, dan event. Bisa berubah kapan saja karena transaksi orang lain.
  • State wallet. Akun aktif, chain aktif, dan status koneksi. Bisa berubah tanpa aplikasimu melakukan apa pun.
  • State UI. Tab, input, toast, dan modal. Ini milikmu, tetapi tidak boleh dianggap bukti kebenaran.

Kesalahan pemula adalah menyimpan address hasil connect di localStorage lalu menganggapnya login. Address mudah dipalsukan di sisi klien. Untuk autentikasi, pengguna harus menandatangani pesan dengan nonce yang diterbitkan server, lalu server memverifikasi signature. Itu dibahas di Bab 10 dan Bab 16.

Kenapa Next.js, bukan HTML biasa

Untuk satu tombol connect, HTML dan JavaScript biasa cukup. Untuk aplikasi yang tumbuh, Next.js memberi routing, pemisahan server dan client, optimasi aset, dan tempat untuk menaruh logika server seperti verifikasi signature. App Router memaksa kamu memikirkan batas: komponen server tidak bisa memakai hook wallet, sedangkan komponen client tidak bisa membaca secret server.

Halaman marketing, dokumentasi, dan daftar kontrak bisa dirender di server. Panel wallet, tombol transaksi, dan event feed harus client. Pemisahan ini bukan gaya penulisan; ia mencegah error hidrasi dan mencegah kunci rahasia masuk ke bundle browser.

Cocok untuk Next.js

  • Landing page dan dokumentasi yang perlu SEO.
  • Dashboard dengan banyak route dan komponen.
  • Endpoint server untuk verifikasi signature dan metadata.
  • Tim yang sudah memakai React dan TypeScript.

Tetap bisa tanpa Next.js

  • Prototipe satu halaman di Remix atau Vite.
  • Widget yang ditempel ke situs yang sudah ada.
  • Aplikasi internal yang tidak butuh SSR.
  • Eksperimen cepat sebelum memilih arsitektur.

Provider di root layout

Provider harus membungkus semua komponen yang memakai hook Wagmi. Tempat paling aman adalah root layout. Karena provider memakai hook dan menyimpan QueryClient, file provider diberi "use client". Layout tetap server component dan mengimpor provider seperti komponen biasa.

app/providers.tsx
"use client";

import { useState, type ReactNode } from "react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { WagmiProvider } from "wagmi";
import { config } from "@/lib/wagmi";

export function Providers({ children }: { children: ReactNode }) {
  const [queryClient] = useState(() => new QueryClient());

  return (
    <WagmiProvider config={config}>
      <QueryClientProvider client={queryClient}>
        {children}
      </QueryClientProvider>
    </WagmiProvider>
  );
}

Mengapa useState(() => new QueryClient())? Di server dan saat hot reload, modul bisa dievaluasi ulang. Membuat QueryClient di level modul berisiko berbagi cache antar request. Dengan state lazy, setiap pohon React mendapat client sendiri.

Hidrasi: saat server dan browser tidak sepakat

Hidrasi adalah proses React mencocokkan HTML dari server dengan pohon komponen di browser. Wallet tidak ada saat server merender. Jika markup awal di server berbeda dengan markup setelah wallet membaca window.ethereum, React melaporkan hydration mismatch.

Wagmi menyediakan opsi ssr: true pada config dan penyimpanan cookie untuk state koneksi. Untuk aplikasi kecil, pola yang paling mudah: render tampilan netral di server, lalu tampilkan status wallet setelah komponen client terpasang. Jangan membaca window di luar useEffect atau event handler.

Pola aman untuk status koneksi
"use client";

import { useEffect, useState } from "react";
import { useAccount } from "wagmi";

export function WalletStatus() {
  const { address, isConnected } = useAccount();
  const [mounted, setMounted] = useState(false);

  useEffect(() => setMounted(true), []);

  if (!mounted) {
    return <span className="wallet-chip">memeriksa wallet...</span>;
  }

  return (
    <span className="wallet-chip" data-on={isConnected}>
      {isConnected && address ? address : "belum terhubung"}
    </span>
  );
}
Bukan hanya soal wallet

Tanggal, Math.random(), dan localStorage juga bisa menyebabkan mismatch. Aturan umumnya: nilai yang hanya diketahui browser jangan dipakai saat render pertama. Tampilkan placeholder yang sama di server dan klien, lalu perbarui setelah mount.

Bab 04FONDASI

Wagmi mengurus React. Viem mengurus Ethereum.

Keduanya sering disebut bersamaan, tetapi pekerjaannya berbeda. Wagmi memberi hook yang reaktif terhadap akun, chain, dan cache. Viem memberi client dan tipe untuk menyusun panggilan, membaca chain, dan memverifikasi data. Kamu akan memakai keduanya, kadang di file yang sama.

  • Membedakan pekerjaan hook Wagmi dan client Viem.
  • Mengonfigurasi Wagmi dengan createConfig dan transport.
  • Mendaftarkan tipe config agar hook mendapat inferensi TypeScript.
  • Memakai usePublicClient dan useWalletClient saat hook belum cukup.

Dua lapisan, satu tujuan

Viem adalah library TypeScript untuk Ethereum. Ia meng-encode ABI, mengirim JSON-RPC, membaca receipt, dan mengembalikan hasil bertipe. Ia tidak tahu apa-apa tentang React. Wagmi adalah lapisan React di atas Viem: ia menyimpan koneksi wallet, menyediakan hook, dan memakai TanStack Query untuk cache.

Config adalah pusat koneksi

Satu file config menyimpan daftar chain, transport RPC, dan connector. Semua hook membaca config ini lewat context. Jangan membuat config baru di dalam komponen; itu membuat cache dan koneksi terpisah.

lib/wagmi.ts
import { createConfig, http } from "wagmi";
import { mainnet, sepolia, anvil } from "wagmi/chains";
import { injected } from "wagmi/connectors";

export const config = createConfig({
  chains: [sepolia, mainnet, anvil],
  connectors: [injected()],
  transports: {
    [sepolia.id]: http(),
    [mainnet.id]: http(),
    [anvil.id]: http("http://127.0.0.1:8545"),
  },
  ssr: true,
});

declare module "wagmi" {
  interface Register {
    config: typeof config;
  }
}

Blok declare module "wagmi" mendaftarkan tipe config. Tanpa itu, TypeScript tidak tahu chain mana yang tersedia dan hasil hook menjadi terlalu umum. Ini bukan dekorasi; ia yang membuat chainId dan useSwitchChain punya tipe yang benar.

Saat hook belum cukup

Kadang kamu butuh client mentah: memanggil beberapa fungsi sekaligus, membaca log historis, atau menyiapkan data di server. Wagmi menyediakan usePublicClient untuk client baca dan useWalletClient untuk client yang bisa menandatangani. Di server, buat public client Viem sendiri.

Memakai public client dari komponen
"use client";

import { usePublicClient } from "wagmi";
import { parseAbiItem } from "viem";

const depositedEvent = parseAbiItem(
  "event Deposited(address indexed user, uint256 amount)"
);

export function useHistoricalDeposits(address: `0x${string}`) {
  const publicClient = usePublicClient();

  return async () => {
    if (!publicClient) return [];
    return publicClient.getLogs({
      address,
      event: depositedEvent,
      fromBlock: 0n,
      toBlock: "latest",
    });
  };
}
Jangan mencampur cache

Jika kamu mengambil data dengan publicClient langsung, hasilnya tidak otomatis masuk cache TanStack Query. Komponen lain yang memakai useReadContract tidak akan ikut diperbarui. Pilih satu jalur untuk satu data, atau bungkus panggilan manual dengan useQuery dan query key yang konsisten.

BigInt, desimal, dan tampilan

Chain tidak mengenal angka desimal. Saldo 0.01 ETH dikirim sebagai 10000000000000000n wei. Viem menyediakan parseEther, formatEther, parseUnits, dan formatUnits. Jangan memakai Number untuk nilai wei; presisi 18 desimal melebihi batas aman floating point.

Konversi yang benar
import { formatEther, parseEther, formatUnits } from "viem";

const wei = parseEther("0.01");       // 10000000000000000n
const eth = formatEther(wei);           // "0.01"

const usdc = 1_250_000n;                // 1.25 USDC, 6 desimal
const tampil = formatUnits(usdc, 6);    // "1.25"

Untuk input pengguna, validasi string sebelum parseEther. String kosong, koma desimal, dan nominal negatif akan melempar error. Tampilkan pesan yang menunjuk input, bukan stack trace.

Bab 05PRAKTIK

Satu aplikasi, beberapa chain, satu chain aktif.

Config menentukan chain apa yang dikenali aplikasi, endpoint RPC mana yang dipakai untuk membaca, dan connector mana yang boleh dipakai wallet. Kesalahan di sini biasanya muncul sebagai "chain tidak dikenali" atau saldo yang tidak pernah berubah.

  • Mendaftarkan chain testnet, mainnet, dan lokal dengan benar.
  • Memilih transport RPC dan memahami konsekuensi endpoint publik.
  • Membedakan connector injected, MetaMask, dan WalletConnect.
  • Menangani chain aktif yang berbeda dari chain aplikasi.

Chain adalah konfigurasi, bukan tebakan

Setiap chain punya chain id. Sepolia 11155111, Ethereum mainnet 1, Anvil 31337. Jika chain tidak ada di array chains, Wagmi tidak bisa membuat transport dan hook akan menolak. Daftarkan hanya chain yang benar-benar kamu dukung; setiap tambahan membawa RPC, eksplorer, dan risiko salah jaringan.

Chain dan transport dengan env
import { createConfig, http, fallback } from "wagmi";
import { sepolia, mainnet, anvil } from "wagmi/chains";
import { injected } from "wagmi/connectors";

const sepoliaRpc = process.env.NEXT_PUBLIC_SEPOLIA_RPC;

export const config = createConfig({
  chains: [sepolia, mainnet, anvil],
  connectors: [injected()],
  transports: {
    [sepolia.id]: sepoliaRpc
      ? fallback([http(sepoliaRpc), http()])
      : http(),
    [mainnet.id]: http(),
    [anvil.id]: http("http://127.0.0.1:8545"),
  },
  ssr: true,
});

fallback mencoba endpoint pertama lalu pindah ke berikutnya jika gagal. Ini berguna untuk RPC publik yang kadang membatasi laju. Namun fallback bukan jaminan konsistensi: dua RPC bisa tertinggal beberapa blok. Untuk pembacaan penting, gunakan satu sumber yang jelas dan bandingkan saat nilainya mencurigakan.

Transport bukan sekadar URL

http() tanpa argumen memakai RPC default chain. http("https://...") memakai endpoint sendiri. Ada juga transport webSocket untuk subscription, dan custom untuk provider wallet. Untuk sebagian besar dApp, HTTP cukup. WebSocket berguna jika kamu butuh event instan dalam jumlah besar, tetapi menambah kompleksitas reconnect.

Connector: siapa yang memegang kunci

injected() memakai provider yang disuntikkan wallet ke window.ethereum. metaMask() dari paket connector memakai MetaMask SDK dan mendukung tautan mobile. walletConnect() memungkinkan wallet di ponsel terhubung lewat QR, tetapi membutuhkan project id dan paket tambahan.

Jika pengguna punya beberapa wallet extension, window.ethereum bisa berasal dari wallet yang tidak mereka maksud. Wagmi mendukung penemuan multi-provider EIP-6963; tampilkan pilihan wallet jika kamu mendukung lebih dari satu. Untuk latihan, satu connector injected sudah cukup.

"use client";

import { useAccount, useSwitchChain } from "wagmi";
import { sepolia } from "wagmi/chains";

export function NetworkGuard() {
  const { chainId } = useAccount();

Bab 06PRAKTIK

Connect adalah permintaan izin, bukan login.

Tombol hubungkan meminta wallet mengungkapkan address dan mengizinkan aplikasi mengirim permintaan tanda tangan. Ia tidak memindahkan dana, tidak memberi akses ke kunci, dan tidak membuktikan siapa pengguna sampai ada signature yang diverifikasi.

  • Membuat tombol connect dengan connector injected.
  • Menangani state menunggu, penolakan, dan disconnect.
  • Menampilkan address pendek dan aksi salin.
  • Memahami apa yang sebenarnya disetujui pengguna saat connect.

Alur yang terlihat oleh pengguna

Pengguna klik tombol. Aplikasi memanggil connector. Wallet menampilkan popup berisi domain, akun yang diminta, dan izin. Jika pengguna setuju, wallet mengembalikan address dan chain. Jika menolak, promise gagal dengan error yang biasanya berisi kode 4001. Setelah terhubung, aplikasi bisa membaca saldo dan meminta tanda tangan, tetapi setiap permintaan baru tetap butuh persetujuan.

components/connect-button.tsx
"use client";

import { useAccount, useConnect, useDisconnect } from "wagmi";
import { injected } from "wagmi/connectors";

function shortAddress(address: string) {
  return `${address.slice(0, 6)}...${address.slice(-4)}`;
}

export function ConnectButton() {
  const { address, isConnecting, isConnected } = useAccount();
  const { connect, isPending, error } = useConnect();
  const { disconnect } = useDisconnect();

  if (isConnected && address) {
    return (
      <div className="connected">
        <code title={address}>{shortAddress(address)}</code>
        <button type="button" onClick={() => disconnect()}>
          Putuskan
        </button>
      </div>
    );
  }

  return (
    <div>
      <button
        type="button"
        onClick={() => connect({ connector: injected() })}
        disabled={isPending || isConnecting}
      >
        {isPending || isConnecting ? "Menunggu wallet..." : "Hubungkan wallet"}
      </button>
      {error ? <p role="alert">{error.message}</p> : null}
    </div>
  );
}

Contoh di atas membuat connector saat klik. Untuk aplikasi nyata, lebih baik mengambil connector dari hasil useConnect() atau mendefinisikannya sekali di config. Membuat objek baru pada setiap render bisa membuat referensi tidak stabil. Gunakan connector yang sudah terdaftar.

Versi yang memakai connector terdaftar
"use client";

import { useConnect } from "wagmi";

export function ConnectButton() {
  const { connectors, connect, isPending, error } = useConnect();
  const injectedConnector = connectors.find(
    (connector) => connector.id === "injected"
  );

  return (
    <button
      type="button"
      disabled={!injectedConnector || isPending}
      onClick={() => {
        if (injectedConnector) connect({ connector: injectedConnector });
      }}
    >
      {isPending ? "Menunggu wallet..." : "Hubungkan MetaMask"}
    </button>
  );
}

Yang tidak dilakukan connect

  • Tidak membuktikan identitas. Siapa pun bisa menghubungkan address yang bukan miliknya jika wallet-nya diatur begitu. Bukti datang dari signature.
  • Tidak memberi izin transfer. Persetujuan token (approval) adalah transaksi terpisah.
  • Tidak menyimpan sesi di server. Aplikasi hanya tahu wallet terhubung di browser ini.
  • Tidak membaca saldo secara otomatis tanpa RPC. Connect hanya memberi address; pembacaan tetap lewat provider atau RPC.
  • Tidak melindungi dari situs palsu. Domain yang dilihat pengguna di popup wallet adalah pertahanan utama. Pastikan domain produksi benar.

Bab 07PRAKTIK

Address adalah identitas, balance adalah potret sesaat.

Setelah wallet terhubung, kamu punya address. Tetapi saldo tidak ikut terkirim bersama address. Saldo harus dibaca dari chain, bisa berubah karena transaksi orang lain, dan bisa berbeda di setiap blok. Tampilkan sebagai data yang punya waktu dan sumber.

  • Menampilkan address aktif dengan format pendek dan aksi salin.
  • Membaca saldo native token memakai useBalance.
  • Menangani loading, error, dan refetch tanpa mengubah state global.
  • Membedakan saldo wallet dan saldo di dalam kontrak.

Address: panjang, mudah salah, dan publik

Address Ethereum adalah 20 byte, ditulis sebagai 42 karakter heksadesimal. Ia publik dan aman ditampilkan. Yang tidak boleh ditampilkan adalah private key atau seed phrase. Untuk UI, tampilkan versi pendek 0x7a9f...4c21 dengan elemen title berisi alamat lengkap, dan tombol salin.

Jangan memotong address dengan asumsi jumlah karakter. Beberapa alamat bisa terlihat mirip di empat karakter terakhir. Untuk transaksi bernilai besar, tampilkan alamat lengkap atau minta pengguna memeriksa di wallet. Ini bukan paranoia; ada serangan alamat mirip yang mengandalkan mata manusia.

"use client";

Bab 08PRAKTIK

ABI adalah kontrak antara JavaScript dan bytecode.

Kontrak tidak mengenal nama fungsi saat runtime. Ia mengenal selector empat byte dan argumen yang di-encode. ABI memberi tahu Viem cara mengubah balanceOf(address) menjadi byte yang benar, lalu mengubah hasilnya kembali menjadi bigint.

  • Menulis ABI minimal sebagai konstanta TypeScript.
  • Memanggil fungsi view dengan useReadContract.
  • Menangani alamat kosong, ABI salah, dan hasil bigint.
  • Memakai useReadContracts untuk beberapa pembacaan sekaligus.

Fungsi view tidak mengubah state

Fungsi view dan pure bisa dipanggil tanpa transaksi. Tidak ada gas, tidak ada tanda tangan, dan tidak ada perubahan state. Hasilnya dibaca dari node yang mungkin sedikit tertinggal. Ini cocok untuk saldo, total supply, pemilik, dan konfigurasi.

Fungsi yang mengubah state, seperti deposit atau withdraw, membutuhkan transaksi bertanda tangan dan biaya gas. Keduanya memakai ABI yang sama, tetapi jalur pemanggilannya berbeda.

ABI minimal untuk MiniVault

    name: "totalDeposits",

Membaca satu nilai

components/vault-balance.tsx
"use client";

import { useAccount, useReadContract } from "wagmi";
import { formatEther } from "viem";
import { miniVaultAbi } from "@/contracts/mini-vault.abi";
import { vaultAddress } from "@/contracts/addresses";

export function VaultBalance() {
  const { address } = useAccount();

  const { data, isLoading, isError, error, refetch } = useReadContract({
    address: vaultAddress,
    abi: miniVaultAbi,
    functionName: "balanceOf",
    args: address ? [address] : undefined,
    query: {
      enabled: Boolean(address),
      refetchInterval: 4_000,
    },
  });

  if (!address) return <p>Hubungkan wallet dulu.</p>
  if (isLoading) return <p>Membaca vault...</p>;
  if (isError) {
    return (
      <div role="alert">
        <p>Gagal membaca kontrak: {error.message}</p>
        <button type="button" onClick={() => refetch()}>Coba lagi</button>
      </div>
    );
  }

  return (
    <p>
      Saldo vault: <strong>{data === undefined ? "--" : formatEther(data)} ETH</strong>
    </p>
  );
}

Argumen args harus sesuai urutan dan tipe ABI. Jika ABI mengatakan address tetapi kamu mengirim string biasa, TypeScript menolak. Jika ABI salah, panggilan bisa revert atau mengembalikan data yang tidak masuk akal. Alamat kontrak dan ABI harus berasal dari build yang sama.

ABI tidak membuktikan kontrak

Siapa pun bisa membuat ABI yang terlihat benar untuk alamat yang salah. ABI hanya menjelaskan antarmuka. Pastikan alamat kontrak berasal dari deploy yang kamu percaya, dan verifikasi source code di explorer atau Sourcify.

Transaksi adalah permintaan yang tidak bisa ditarik kembali.

Membaca kontrak hanya mengirim pertanyaan. Menulis kontrak mengirim permintaan yang, jika ditambang, mengubah state secara permanen. Frontend harus memperlambat pengguna di titik ini: tampilkan nominal, tujuan, fungsi, dan biaya sebelum wallet meminta tanda tangan.

  • Menyusun transaksi deposit dengan useWriteContract.
  • Mensimulasikan transaksi sebelum meminta tanda tangan.
  • Menampilkan hash, status menunggu, dan receipt.
  • Mencegah klik ganda dan memperbarui data setelah sukses.

Isi sebuah transaksi

Transaksi berisi pengirim, penerima, nilai ETH, data calldata, gas limit, harga gas, nonce, dan chain id. Untuk memanggil deposit(), penerima adalah alamat kontrak, nilai adalah nominal, dan calldata adalah selector fungsi. Wallet menambahkan nonce dan menandatangani; kamu tidak mengisinya sendiri.

Simulasikan sebelum menandatangani

useSimulateContract menjalankan panggilan terhadap state terbaru tanpa mengirim transaksi. Jika kontrak akan revert, simulasi memberi error sebelum wallet terbuka. Ini menghemat waktu dan memberi pesan yang lebih jelas. Simulasi bukan jaminan: state bisa berubah sebelum transaksi masuk blok.

Verifikasi di server

Server harus menyimpan nonce yang diterbitkan, memeriksa apakah nonce masih berlaku, lalu memanggil verifyMessage. Jika valid, nonce dihapus dan sesi dibuat. Jangan memverifikasi di browser lalu mengirim boolean "valid" ke server; penyerang bisa mengirim true tanpa signature.

app/api/verify/route.ts
import { NextResponse } from "next/server";
import { verifyMessage, isAddress } from "viem";

export async function POST(request: Request) {
  const body = await request.json();
  const { address, message, signature } = body;

  if (!isAddress(address) || typeof message !== "string") {
    return NextResponse.json({ error: "Input tidak valid" }, { status: 400 });
  }

  const valid = await verifyMessage({
    address,
    message,
    signature,
  });

  if (!valid) {
    return NextResponse.json({ error: "Signature tidak valid" }, { status: 401 });
  }

  // Di produksi: cek nonce, domain, chain, dan waktu kedaluwarsa.
  // Lalu buat sesi HttpOnly, bukan mengembalikan "loggedIn: true" saja.
  return NextResponse.json({ ok: true });
}

Event adalah catatan masa lalu yang bisa dibaca ulang.

Kontrak dapat mengeluarkan event saat state berubah. Event lebih murah daripada storage dan mudah diindeks, tetapi tidak bisa dibaca oleh kontrak lain. Frontend memakainya untuk riwayat aktivitas, notifikasi, dan analitik. Untuk keputusan yang bergantung pada state terkini, tetap panggil fungsi view.

  • Menjelaskan struktur log: address, topic, data, dan blok.
  • Berlangganan event baru dengan useWatchContractEvent.
  • Membaca log historis dengan getLogs.
  • Menghindari ketergantungan pada event untuk kebenaran state.

Bagaimana event disimpan

Event tidak disimpan di storage kontrak. Saat dieksekusi, EVM menghasilkan log yang menempel pada receipt. Log berisi alamat kontrak, topik (signature event dan parameter indexed), data untuk parameter non-indexed, nomor blok, hash transaksi, dan indeks log. Node menyimpan log dan bisa menyaringnya berdasarkan alamat dan topik.

Event di kontrak
event Deposited(address indexed user, uint256 amount);
event Withdrawn(address indexed user, uint256 amount);

function deposit() external payable {
    if (msg.value == 0) revert ZeroAmount();
    balanceOf[msg.sender] += msg.value;
    totalDeposits += msg.value;
    emit Deposited(msg.sender, msg.value);
}

Parameter indexed masuk ke topik dan bisa difilter. Parameter non-indexed masuk ke data dan tidak bisa difilter langsung. Topik pertama adalah hash signature event, misalnya Deposited(address,uint256). Karena itu nama dan tipe parameter harus konsisten dengan ABI.

Berlangganan event baru

"use client";

import { useState } from "react";
import { useWatchContractEvent } from "wagmi";
import { formatEther } from "viem";
import { miniVaultAbi } from "@/contracts/mini-vault.abi";
import { vaultAddress } from "@/contracts/addresses";

type DepositLog = {
  user: `0x${string}`;
  amount: bigint;
  blockNumber: bigint;
  transactionHash: `0x${string}`;
};

export function EventFeed() {
  const [logs, setLogs] = useState<DepositLog[]>([]);

  useWatchContractEvent({
    address: vaultAddress,
    abi: miniVaultAbi,
    eventName: "Deposited",
    poll: true,
    onLogs(incoming) {
      setLogs((previous) => [
        ...incoming.map((log) => ({
          user: log.args.user,
          amount: log.args.amount,
          blockNumber: log.blockNumber,
          transactionHash: log.transactionHash,
        })),
        ...previous,
      ]);
    },
  });

  return (
    <ul>
      {logs.map((log) => (
        <li key={`${log.transactionHash}-${log.blockNumber}`}>
          {log.user} deposit {formatEther(log.amount)} ETH di blok{" "}
          {log.blockNumber.toString()}
        </li>
      ))}
    </ul>
  );
}

Hook ini hanya menangkap event baru setelah komponen aktif. Ia tidak memuat riwayat lama. Jika halaman di-refresh, daftar kosong lagi. Opsi poll: true membuat Wagmi memeriksa log baru secara berkala saat transport HTTP tidak menyediakan subscription. Untuk riwayat, gabungkan dengan getLogs atau indexer. Untuk aplikasi produksi dengan banyak event, indexer seperti Ponder, Subsquid, atau The Graph lebih tepat daripada memindai rantai di browser.

      title: "Saldo tidak cukup",
      detail: "Saldo harus menutup nominal dan biaya gas.",
      retry: false,
    };
  }

  if (message.includes("Chain mismatch")) {
    return {
      title: "Chain tidak sesuai",
      detail: "Pindah ke Sepolia sebelum mengirim transaksi.",
      retry: false,
    };
  }

  if (message.includes("429")) {
    return {
      title: "RPC sedang membatasi permintaan",
      detail: "Tunggu sebentar, lalu muat ulang data.",
      retry: true,
    };
  }

  return {
    title: "Permintaan gagal",
    detail: "Coba lagi. Jika tetap gagal, periksa wallet dan jaringan.",
    retry: true,
  };
}

    Jangan pernah menampilkan private key, seed phrase, atau isi request mentah ke UI. Error bisa memuat data sensitif dari provider. Log detail ke konsol saat pengembangan, tetapi kirim pesan yang sudah disaring ke pengguna.

    Hook domain, bukan hook di mana-mana

    Jika lima komponen memanggil useReadContract untuk data yang sama, pindahkan ke satu hook domain. Hook itu boleh memanggil beberapa hook Wagmi dan mengembalikan bentuk yang nyaman untuk UI. Ini mengurangi duplikasi query key dan memusatkan penanganan error.

    hooks/use-vault.ts
    "use client";

import { useAccount, useReadContract } from "wagmi";
import { formatEther } from "viem";
import { miniVaultAbi } from "@/contracts/mini-vault.abi";
import { getVaultAddress } from "@/contracts/addresses";

export function useVault() {
  const { address, chainId } = useAccount();
  const vault = getVaultAddress(chainId);

  const balanceQuery = useReadContract({
    address: vault,
    abi: miniVaultAbi,
    functionName: "balanceOf",
    args: address ? [address] : undefined,
    query: { enabled: Boolean(address && vault) },
  });

  return {
    vault,
    rawBalance: balanceQuery.data,
    balance: balanceQuery.data === undefined
      ? undefined
      : formatEther(balanceQuery.data),
    isLoading: balanceQuery.isLoading,
    isError: balanceQuery.isError,
    refetch: balanceQuery.refetch,
  };
}

    Kontrak MiniVault

    src/MiniVault.sol
    // SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract MiniVault {
    mapping(address => uint256) public balanceOf;
    uint256 public totalDeposits;

    event Deposited(address indexed user, uint256 amount);
    event Withdrawn(address indexed user, uint256 amount);

    error ZeroAmount();
    error InsufficientBalance(uint256 available, uint256 requested);

    function deposit() external payable {
        if (msg.value == 0) revert ZeroAmount();
        balanceOf[msg.sender] += msg.value;
        totalDeposits += msg.value;
        emit Deposited(msg.sender, msg.value);
    }

    function withdraw(uint256 amount) external {
        uint256 available = balanceOf[msg.sender];
        if (amount == 0) revert ZeroAmount();
        if (amount > available) {
            revert InsufficientBalance(available, amount);
        }

        balanceOf[msg.sender] = available - amount;
        totalDeposits -= amount;
        emit Withdrawn(msg.sender, amount);

        (bool ok, ) = msg.sender.call{value: amount}("");
        require(ok, "ETH transfer failed");
    }
}

    Kontrak ini menjaga urutan checks-effects-interactions: saldo dikurangi sebelum ETH dikirim. Untuk produksi, tambahkan reentrancy guard, batas ukuran, dan test yang lebih lengkap. Latihan ini fokus pada frontend; jangan menganggap kontrak contoh ini sudah diaudit.

    Glosarium

    ABI
    Deskripsi antarmuka kontrak: fungsi, event, argumen, dan return. Viem memakai ABI untuk encode dan decode.
    Address
    Identitas 20 byte di Ethereum, ditulis 42 karakter heksadesimal. Publik dan aman ditampilkan.
    Approval
    Izin yang diberikan pemilik token kepada alamat lain untuk menarik token hingga batas tertentu.
    BigInt
    Tipe JavaScript untuk bilangan bulat besar. Viem mengembalikan uint256 sebagai bigint.
    Calldata
    Data yang dikirim bersama transaksi: selector fungsi dan argumen yang di-encode.
    Chain id
    Angka identitas chain. Sepolia 11155111, Ethereum 1, Anvil 31337.
    Connector
    Adaptor yang menghubungkan aplikasi ke wallet, misalnya injected, MetaMask SDK, atau WalletConnect.
    Confirmation
    Jumlah blok setelah blok transaksi. Semakin banyak, semakin kecil kemungkinan reorg membatalkannya.
    Dropped
    Transaksi yang hilang dari mempool dan tidak masuk blok. Bisa karena biaya terlalu rendah atau node membuangnya.
    EIP-191
    Standar prefix untuk menandatangani pesan teks, dipakai personal_sign.
    EIP-712
    Standar tanda tangan data terstruktur dengan domain dan tipe.
    EIP-4361
    Sign-In with Ethereum. Format pesan login yang memuat domain, address, nonce, dan chain.
    EIP-6963
    Standar penemuan beberapa provider wallet di browser.
    Event log
    Catatan yang dihasilkan kontrak saat dieksekusi. Berisi topik, data, blok, dan hash transaksi.
    Gas
    Biaya komputasi transaksi. Dibayar dalam ETH dan tetap dikenakan walau transaksi revert.
    Hash transaksi
    Identitas transaksi. Adanya hash belum berarti transaksi berhasil.
    Hydration
    Proses React mencocokkan HTML server dengan komponen browser. Perbedaan markup memicu hydration mismatch.
    Injected provider
    Provider wallet yang disuntikkan ke window.ethereum oleh extension atau browser wallet.
    Log
    Lihat event log. Bisa difilter berdasarkan alamat, topik, dan rentang blok.
    Mempool
    Kumpulan transaksi yang menunggu untuk dimasukkan ke blok.
    Nonce
    Penghitung transaksi per akun. Juga dipakai sebagai nilai sekali pakai dalam pesan login.
    Public client
    Client Viem untuk membaca chain tanpa private key.
    Query key
    Kunci cache TanStack Query. Wagmi memasukkan address dan chain ke key untuk data kontrak.
    Receipt
    Bukti transaksi setelah masuk blok. Berisi status success atau reverted, gas used, dan log.
    Reorg
    Reorganisasi blok yang membatalkan blok sebelumnya. Log bisa ditandai removed.
    Replaced
    Transaksi dengan nonce yang sama digantikan transaksi lain, biasanya dengan biaya lebih tinggi.
    RPC
    Endpoint JSON-RPC yang menghubungkan frontend ke node Ethereum.
    Selector
    Empat byte pertama hash signature fungsi, dipakai untuk menunjuk fungsi di calldata.
    Simulate
    Menjalankan panggilan terhadap state tanpa mengirim transaksi, untuk memprediksi revert dan gas.
    SSR
    Server-side rendering. Di Wagmi, opsi ssr membantu hidrasi state koneksi.
    Topic
    Nilai 32 byte di log. Topik pertama adalah signature event; parameter indexed mengisi topik berikutnya.
    Transport
    Jalur komunikasi ke chain: HTTP, WebSocket, fallback, atau custom provider.
    Wallet client
    Client Viem yang bisa meminta tanda tangan dan mengirim transaksi melalui wallet.
    Wei
    Satuan terkecil ETH. 1 ETH = 1018 wei.

    Error yang sering muncul

    Catatan
    User rejected request        -> penolakan wallet, bukan bug
insufficient funds           -> saldo < nominal + gas
Chain mismatch               -> bandingkan chainId, minta switch
nonce too low                -> transaksi lain sudah memakai nonce
429 Too Many Requests        -> RPC membatasi, coba lagi
hydration mismatch           -> jangan baca window saat render server
ABI encoding error           -> tipe argumen tidak cocok dengan ABI
    Cara memakai cheatsheet

    Jangan menyalin semua potongan sekaligus. Pilih satu alur, jalankan di proyek latihan, lalu baca error yang muncul. Kode yang tidak kamu pahami error-nya belum kamu kuasai.
