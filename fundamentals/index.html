Bab 01FONDASI

JavaScript adalah bahasa. Runtime yang menentukan kapan ia berjalan.

Sebelum menyalahkan promise atau API, kamu perlu tahu ke mana kode pergi. JavaScript menjalankan satu tumpukan panggilan pada satu waktu. Pekerjaan yang menunggu (timer, network, event klik) dititipkan ke runtime, lalu dikembalikan lewat antrean saat tumpukan kosong.

  • Membedakan bahasa JavaScript dari runtime browser dan Node.js.
  • Menjelaskan call stack, heap, Web API, dan antrean task.
  • Membaca urutan output kode yang mencampur sinkron, promise, dan timer.
  • Mengenali pekerjaan yang memblokir UI dan pekerjaan yang tidak.

Satu bahasa, dua runtime yang berbeda

JavaScript adalah spesifikasi bahasa: sintaks, tipe, operator, dan aturan eksekusi. Browser dan Node.js sama-sama menjalankan JavaScript, tetapi mereka memberi benda yang berbeda. Browser memberi document, window, dan fetch. Node memberi process, fs, dan akses jaringan tingkat rendah. Fungsi yang sama bisa berjalan di keduanya, tetapi kode yang menyentuh document akan gagal di Node.

Next.js memakai keduanya sekaligus. Server component berjalan di Node, client component berjalan di browser. Itu sebabnya kode yang memakai window harus berada di client, dan kode yang memegang secret harus berada di server. Batas ini bukan detail arsitektur; ia menentukan apa yang bisa bocor ke pengguna.

Call stack, heap, dan antrean

Bayangkan tiga tempat. Call stack menyimpan fungsi yang sedang berjalan. Heap menyimpan object dan nilai yang dialokasikan. Antrean menyimpan callback yang siap dijalankan setelah stack kosong. Runtime browser menambahkan Web API untuk timer, network, dan event. Node memakai libuv dengan peran yang serupa.

Kode sinkron selalu selesai lebih dulu. Promise memakai microtask. Timer dan event memakai macrotask. Itu sebabnya setTimeout(..., 0) tidak pernah benar-benar berjalan sebelum kode setelahnya.

Membaca urutan output

Contoh berikut adalah pertanyaan interview klasik, tetapi alasannya praktis: kamu perlu tahu kapan state UI diperbarui setelah request. Baca kodenya, tebak urutannya, baru jalankan di browser.

event-loop.js
console.log("1: sync");

setTimeout(() => {
  console.log("4: timer");
}, 0);

Promise.resolve().then(() => {
  console.log("3: promise");
});

console.log("2: sync");

Urutannya 1, 2, 3, 4. Log pertama dan terakhir berjalan di stack yang sama. Callback promise masuk ke antrean microtask dan dikuras setelah stack kosong. Timer baru dijalankan pada putaran event loop berikutnya.

Kalau kamu memakai await, bagian setelah await juga berjalan sebagai microtask. Itu penting saat kamu mengira state sudah diperbarui, padahal React belum sempat merender ulang.

Inti bab

JavaScript tidak berjalan paralel untuk kode JavaScript biasa. Ia mengatur pekerjaan asinkron lewat antrean. Operasi jaringan dan timer menunggu di luar stack, tetapi callback-nya tetap berjalan satu per satu.

Latihan

Tanpa membuka browser, tentukan urutan output dari kode berikut: console.log("A"), Promise.resolve().then(() => console.log("B")), setTimeout(() => console.log("C"), 0), console.log("D").

Lihat jawaban

A, D, B, C. A dan D sinkron. B adalah microtask Promise. C adalah macrotask timer, dijalankan setelah antrean microtask kosong. Lab 06 membuktikannya dengan waktu eksekusi nyata di browser.

Bab 02BAHASA

Nilai punya tipe. Kesamaan punya aturan. Jangan menebak.

JavaScript tidak meminta kamu menulis tipe, tetapi setiap nilai tetap punya tipe. Sebagian besar bug pemula berasal dari dua kebiasaan: memakai == dan menganggap semua angka bisa diperlakukan sama. Bab ini memasang aturan dasarnya.

  • Menyebut tujuh primitive dan membedakannya dari object.
  • Memahami typeof null, NaN, dan nilai falsy.
  • Memilih === atau Object.is sesuai kebutuhan.
  • Memakai optional chaining dan nullish coalescing tanpa menelan error.

Tujuh primitive, satu object

Primitive disalin berdasarkan nilai. Object disalin berdasarkan referensi. Ini bukan detail akademis: kalau kamu mengirim object ke fungsi lalu mengubahnya, pemanggil ikut melihat perubahan. Kalau kamu mengirim string, pemanggil tidak terpengaruh.

Primitive

  • string: teks, tidak bisa diubah di tempat.
  • number: floating point 64 bit.
  • bigint: integer presisi arbitrer.
  • boolean: true atau false.
  • undefined: belum diberi nilai.
  • null: sengaja kosong.
  • symbol: kunci unik, jarang dipakai di aplikasi biasa.

Object

  • Object literal, array, function, Date, Map, Set.
  • Disimpan di heap dan diakses lewat referensi.
  • Dua object dengan isi sama tetap tidak ===.
  • Gunakan structuredClone untuk salinan dalam yang aman.
  • Gunakan spread untuk salinan dangkal.

Lab 01

Tebak hasil, lalu periksa alasan.

Pilih jawaban yang benar untuk setiap ekspresi. Lab ini tidak menilai kecepatan, tetapi menilai apakah kamu tahu aturan di balik hasilnya.

typeof null menghasilkan?

Bug historis. Untuk memeriksa null, gunakan value === null, bukan typeof.

0.1 + 0.2 === 0.3 menghasilkan?

Hasilnya 0.30000000000000004. Floating point biner tidak bisa menyimpan 0.3 secara tepat. BigInt dipakai untuk nilai integer, bukan pecahan.

"5" === 5 menghasilkan?

=== membandingkan tipe dan nilai. String dan number berbeda tipe. "5" == 5 bernilai true karena koersi, dan itulah yang sebaiknya dihindari.

[] === [] menghasilkan?

Dua literal array adalah dua object berbeda. Perbandingan memeriksa referensi, bukan isi. Untuk membandingkan isi, bandingkan elemennya atau pakai fungsi pembanding.

Optional chaining dan nullish coalescing

user.address?.city berhenti dan menghasilkan undefined kalau address bernilai null atau undefined. Ia tidak menyelamatkan kamu dari bentuk data yang salah: kalau address ternyata string, akses properti tetap menghasilkan undefined atau perilaku aneh. Optional chaining mengurangi error null, bukan menggantikan validasi.

optional.js
const user = {
  name: "Rani",
  address: null,
  balanceWei: 0n
};

user.address?.city;              // undefined, tidak melempar error
user.address.city;               // TypeError

user.balanceWei ?? 0n;           // 0n, karena 0n bukan null/undefined
user.missing ?? 10n;             // 10n
user.missing || 10n;             // 10n, tetapi juga mengganti 0 atau ""

// Jangan menelan kesalahan bentuk data.
const city = typeof user.address === "object" && user.address !== null
  ? user.address.city
  : "tidak diketahui";
Jangan pakai == untuk menebak

== melakukan koersi yang sulit dibaca. Satu-satunya pengecualian yang umum adalah value == null untuk menangkap null dan undefined sekaligus, tetapi menulis value === null || value === undefined lebih jelas. Pilih kejelasan.

Latihan

Ubah fungsi berikut agar tidak memakai == dan tetap menangani null: if (value == null) return 0;

Lihat jawaban

if (value === null || value === undefined) return 0;. Alternatif yang eksplisit untuk API adalah memeriksa tipe dengan typeof value !== "number" lalu memvalidasi Number.isFinite, karena data dari jaringan tidak dijamin berupa number.

Bab 03BAHASA

Fungsi adalah unit terkecil yang bisa kamu percaya.

Fungsi bukan hanya pembungkus kode. Ia menentukan input, output, dan state yang boleh diingat. Closure memungkinkan state itu hidup tanpa variabel global. Arrow function mengubah perilaku this. Semuanya perlu dipilih dengan sengaja.

  • Membedakan declaration, expression, dan arrow function.
  • Memakai parameter default, rest, dan spread dengan benar.
  • Menjelaskan closure dan kenapa ia berguna untuk state lokal.
  • Menulis fungsi murni dan mengenali efek samping.

Tiga bentuk, satu tujuan

Function declaration bisa dipanggil sebelum barisnya karena hoisting. Function expression dan arrow function tidak. Arrow function tidak punya this sendiri, tidak punya arguments, dan tidak bisa dipakai sebagai constructor. Di komponen React, arrow function nyaman untuk callback karena this tidak berubah.

bentuk-fungsi.js
// Declaration: hoisted, bisa dipanggil lebih awal
function tambah(a, b) {
  return a + b;
}

// Expression: disimpan di variabel
const kurang = function (a, b) {
  return a - b;
};

// Arrow: ringkas, tidak punya this sendiri
const kali = (a, b) => a * b;

// Default, rest, dan spread
function total(harga, jumlah = 1, ...biayaLain) {
  return harga * jumlah + biayaLain.reduce((sum, item) => sum + item, 0);
}

const angka = [2, 3, 4];
const hasil = tambah(...angka); // spread menjadi argumen terpisah

console.log(total(10, 2, 1, 1)); // 22

Closure: fungsi yang mengingat lingkupnya

Closure terjadi ketika fungsi mengakses variabel dari lingkup luar setelah lingkup itu selesai. Contoh paling berguna adalah counter: setiap counter punya nilai sendiri, dan tidak ada yang bisa mengubahnya dari luar kecuali lewat fungsi yang disediakan.

counter.js
function createCounter(start = 0) {
  let value = start; // hidup selama fungsi yang memakainya hidup

  return {
    increment() {
      value += 1;
      return value;
    },
    reset() {
      value = start;
      return value;
    },
    read() {
      return value;
    }
  };
}

const counterA = createCounter();
const counterB = createCounter(10);

counterA.increment(); // 1
counterA.increment(); // 2
counterB.increment(); // 11
counterA.read();      // 2, tidak terpengaruh counterB

Closure juga dipakai di hook React. Nilai state yang dibaca di dalam callback adalah nilai pada render saat callback dibuat, bukan nilai terbaru. Itu bukan bug React; itu cara closure bekerja. Kalau kamu butuh nilai terbaru, pakai functional update atau ref.

Fungsi murni dan efek samping

Fungsi murni hanya bergantung pada argumen dan tidak mengubah apa pun di luar dirinya. Ia mudah diuji dan mudah diprediksi. Fungsi yang menulis ke database, memanggil API, atau mengubah array global punya efek samping. Efek samping tidak jahat; aplikasi butuh efek samping. Yang penting adalah menempatkannya di batas yang jelas, bukan menyebar di setiap fungsi.

Murni

  • Input sama, output sama.
  • Tidak membaca waktu, random, atau state global.
  • Mengembalikan nilai baru, tidak memutasi argumen.
  • Mudah diuji tanpa mock.

Efek samping

  • Menulis file, database, atau localStorage.
  • Mengirim request jaringan.
  • Mengubah DOM atau memutar audio.
  • Memutasi object yang dipakai pihak lain.
Inti bab

Fungsi yang baik punya nama yang menjelaskan niat, input yang jelas, dan satu alasan untuk berubah. Closure menyimpan state tanpa global. Arrow function bukan pengganti semua function; ia alat untuk callback yang tidak butuh this sendiri.

Latihan

Buat fungsi createRateLimiter(limit) yang mengembalikan fungsi. Setiap pemanggilan menambah hitungan. Kalau hitungan melebihi limit, kembalikan false; jika belum, true. Jelaskan variabel mana yang tertutup closure.

Lihat jawaban

function createRateLimiter(limit) { let used = 0; return () => { used += 1; return used <= limit; }; }. Variabel used tertutup dan hanya bisa diakses oleh fungsi yang dikembalikan. Setiap limiter punya used sendiri.

Bab 04BAHASA

Data datang sebagai daftar. Kekuatanmu ada di pipeline.

Hampir semua data aplikasi berbentuk array of object: daftar transaksi, daftar token, daftar commit. JavaScript memberi operasi yang cukup untuk menyaring, mengubah, dan menjumlahkan data tanpa loop manual. Yang perlu dijaga: banyak metode mengembalikan array baru, beberapa memutasi array asal.

  • Memilih map, filter, reduce, atau find sesuai hasil yang diinginkan.
  • Membedakan metode yang memutasi dan yang mengembalikan salinan.
  • Menulis update object dan array tanpa mengubah data asal.
  • Menjumlahkan nilai wei dengan BigInt di dalam reduce.

pipeline.js
const transactions = [
  { id: 1, type: "deposit", status: "ok", amountWei: 1500000000000000000n },
  { id: 2, type: "withdraw", status: "ok", amountWei: 400000000000000000n },
  { id: 3, type: "deposit", status: "failed", amountWei: 900000000000000000n },
  { id: 4, type: "deposit", status: "ok", amountWei: 250000000000000000n }
];

const totalDeposit = transactions
  .filter((tx) => tx.type === "deposit")
  .filter((tx) => tx.status === "ok")
  .reduce((sum, tx) => sum + tx.amountWei, 0n);

console.log(totalDeposit); // 1750000000000000000n

const symbols = transactions.map((tx) => tx.id);
const hasFailure = transactions.some((tx) => tx.status === "failed");
const sorted = transactions
  .slice()
  .sort((a, b) => (a.amountWei > b.amountWei ? -1 : 1));

Perhatikan 0n sebagai nilai awal reduce. Kalau kamu memakai 0, penjumlahan BigInt akan melempar TypeError karena mencampur Number dan BigInt. Nilai awal harus bertipe sama dengan nilai yang dijumlahkan.

Update tanpa memutasi

Di React, memutasi state tidak memicu render ulang karena referensinya tetap sama. Di kode lain, mutasi membuat perubahan sulit dilacak. Biasakan membuat object baru untuk perubahan.

immutable.js
const token = { symbol: "ETH", decimals: 18, active: true };

// Salah: mengubah object asal
token.active = false;

// Benar: object baru
const updated = { ...token, active: false };

// Array: buang satu item
const next = tokens.filter((item) => item.id !== token.id);

// Array: ganti satu item
const replaced = tokens.map((item) =>
  item.id === token.id ? { ...item, decimals: 6 } : item
);

// Salinan dangkal vs dalam
const shallow = { ...token };

    Promise adalah janji. Ia punya tiga keadaan, bukan dua.

    Promise membungkus pekerjaan yang belum selesai. Ia dimulai sebagai pending, lalu menjadi fulfilled atau rejected. Setelah selesai, nilainya tidak berubah. Memahami tiga keadaan ini membuat kode async jauh lebih mudah dibaca.

    • Menjelaskan pending, fulfilled, dan rejected.
    • Memakai then, catch, dan finally tanpa menelan error.
    • Memilih Promise.all, allSettled, race, atau any.
    • Menjelaskan urutan microtask dan macrotask di browser.

    Dari callback ke promise

    Callback adalah fungsi yang dipanggil saat pekerjaan selesai. Ia bekerja, tetapi sulit dikomposisikan: error harus diteruskan manual, dan urutan bersarang membuat kode sulit dibaca. Promise membalik kendali: fungsi mengembalikan object yang bisa kamu then, sementara error mengalir ke catch terdekat.

    Timeout dan pembatalan

    fetch tidak punya opsi timeout di semua runtime. Pola yang bisa dipakai: buat AbortController, jadwalkan abort(), lalu bersihkan timer setelah request selesai. Ini juga mencegah request lama menimpa state baru saat pengguna berpindah halaman.

    timeout.js
    async function fetchWithTimeout(url, ms = 5000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);

  try {
    const response = await fetch(url, { signal: controller.signal });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (error) {
    if (error.name === "AbortError") {
      throw new Error(`Request melewati batas ${ms} ms`);
    }
    throw error;
  } finally {
    clearTimeout(timer);
  }
}

    Retry dengan backoff

    Retry hanya masuk akal untuk kegagalan sementara: jaringan putus, 429, 500, 502, 503. Jangan retry 400, 401, atau 404 tanpa mengubah input. Beri batas percobaan, jeda yang bertambah, dan hentikan kalau request dibatalkan.

    retry.js
    const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function fetchWithRetry(url, attempts = 3) {
  let lastError;

  for (let attempt = 1; attempt <= attempts; attempt += 1) {
    try {
      return await fetchWithTimeout(url);
    } catch (error) {
      lastError = error;
      if (attempt === attempts) break;
      await sleep(300 * 2 ** (attempt - 1)); // 300, 600, 1200 ms
    }
  }

  throw lastError;
}
    Abort bukan error biasa

    Pembatalan biasanya muncul sebagai DOMException dengan nama AbortError. Jangan tampilkan pesan "server error" untuk pembatalan yang pengguna sendiri picu. Bedakan state batal, gagal, dan sukses di UI.

      TypeScript bukan JavaScript yang lebih sulit. Ia compiler yang menolak tebakan.
      
          
      TypeScript menambahkan pemeriksaan statis di atas JavaScript. Tujuannya bukan membuat kode lebih panjang, tetapi membuat kesalahan bentuk data terlihat sebelum aplikasi berjalan.   return value !== null && typeof value === "object" && !Array.isArray(value);
}

function parseToken(value: unknown): Token {
  if (!isRecord(value)) throw new Error("token bukan object");
  if (typeof value.id !== "string") throw new Error("id tidak valid");
  if (typeof value.symbol !== "string") throw new Error("symbol tidak valid");
  if (typeof value.decimals !== "number" || !Number.isInteger(value.decimals)) {
    throw new Error("decimals tidak valid");
  }
  if (typeof value.supplyWei !== "string" || !/^\d+$/.test(value.supplyWei)) {
    throw new Error("supplyWei harus string digit");
  }

  return {
    id: value.id,
    symbol: value.symbol,
    decimals: value.decimals,
    supplyWei: BigInt(value.supplyWei)
  };
}

      export function parseUnits(value: string, decimals: number): bigint {
  const text = value.trim();
  if (!/^\d+(\.\d*)?$/.test(text)) {
    throw new Error("Format angka tidak valid");
  }
  const [whole, fraction = ""] = text.split(".");
  if (fraction.length > decimals) {
    throw new Error(`Maksimal ${decimals} desimal`);
  }
  const padded = (fraction + "0".repeat(decimals)).slice(0, decimals);
  return BigInt(whole) * 10n ** BigInt(decimals) + BigInt(padded || "0");
}

export function formatUnits(
  value: bigint,
  decimals: number,
  maxFraction = 4
): string {
  const base = 10n ** BigInt(decimals);
  const whole = value / base;
  const raw = (value % base).toString().padStart(decimals, "0");
  const fraction = raw.slice(0, maxFraction).replace(/0+$/, "");
  return fraction ? `${whole}.${fraction}` : whole.toString();
}

export function groupDigits(value: string): string {
  return value.replace(/\B(?=(\d{3})+(?!\d))/g, ".");
}

  return { ...dto, supplyWei: BigInt(dto.supplyWei) };
}

export async function fetchTokens(signal?: AbortSignal): Promise<Token[]> {
  const response = await fetch("/api/tokens", {
    headers: { Accept: "application/json" },
    signal
  });

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  const json: unknown = await response.json();
  if (!isRecord(json) || !Array.isArray(json.data)) {
    throw new Error("Bentuk respons tidak dikenal");
  }

  return json.data.map((item) => toToken(parseDto(item)));
}
      
        
      
        
      response.json() mengembalikan any secara bawaan. Memberinya anotasi unknown memaksa validasi. Setelah parseDto, nilai supplyWei adalah BigInt dan sisa aplikasi tidak perlu tahu bahwa wire memakai string.

      "use client";

import { useCallback, useEffect, useState } from "react";
import { fetchTokens } from "@/lib/tokens";
import { formatUnits, groupDigits } from "@/lib/units";
import type { Token } from "@/types/token";

type State =
  | { status: "loading" }
  | { status: "success"; tokens: Token[] }
  | { status: "empty" }
  | { status: "error"; message: string };

export function TokenBoard() {
  const [state, setState] = useState<State>({ status: "loading" });
  const [attempt, setAttempt] = useState(0);

  useEffect(() => {
    const controller = new AbortController();
    setState({ status: "loading" });

    fetchTokens(controller.signal)
      .then((tokens) => {
        setState(tokens.length ? { status: "success", tokens } : { status: "empty" });
      })
      .catch((error: unknown) => {
        if (error instanceof DOMException && error.name === "AbortError") return;
        setState({
          status: "error",
          message: error instanceof Error ? error.message : "Gagal memuat token"
        });
      });

    return () => controller.abort();
  }, [attempt]);

  const retry = useCallback(() => setAttempt((value) => value + 1), []);

  if (state.status === "loading") return <p>Memuat token...</p>;
  if (state.status === "empty") return <p>Belum ada token.</p>;
  if (state.status === "error") {
    return (
      <div>
        <p>{state.message}</p>
        <button type="button" onClick={retry}>Coba lagi</button>
      </div>
    );
  }

  return (
    <table>
      <thead>
        <tr><th>Simbol</th><th>Desimal</th><th>Supply</th></tr>
      </thead>
      <tbody>
        {state.tokens.map((token) => (
          <tr key={token.id}>
            <td>{token.symbol}</td>
            <td>{token.decimals}</td>
            <td>{groupDigits(formatUnits(token.supplyWei, token.decimals, 2))}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
      
        
      
        
      Perhatikan tiga hal. useEffect membuat controller dan membatalkannya di cleanup. Error pembatalan tidak ditampilkan sebagai kegagalan. Tombol coba lagi menaikkan attempt, sehingga effect berjalan lagi tanpa memindahkan logika fetch ke event handler.
